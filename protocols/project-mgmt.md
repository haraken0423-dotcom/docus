# プロジェクト・案件管理

トリガー: 新規タスク・案件の依頼。

## 目的

依頼を一過性の会話で終わらせず、`projects/` 配下に案件として記録し、状態を追跡できるようにする。

## 新規案件の登録

1. 依頼内容から以下を特定する（不明なものはユーザーに確認するか「未定」と記載）。
   - 案件名
   - 目的・背景
   - 担当・関係者
   - 期限
   - 現在のステータス
2. `projects/<案件名を英数字スラッグ化したもの>.md` を作成し、以下の形式で記録する。

```markdown
# <案件名>

- ステータス: 未着手 / 進行中 / 保留 / 完了
- 期限:
- 関係者:
- 開始日:

## 目的・背景

## タスク

- [ ] タスク内容（担当・期限）

## 経緯・メモ

- YYYY-MM-DD: ...
```

3. 登録したことと、次のアクションが何かを1〜2文で報告する。

## 既存案件の更新

- 進捗報告やタスク完了の連絡を受けたら、該当する `projects/*.md` の「タスク」「経緯・メモ」
  「ステータス」を更新する。
- ステータス変更（特に「完了」「保留」）はユーザーに確認せず反映してよいが、報告時に明示する。

## 注意

- 案件の粒度は「単発の頼まれごと」ではなく「複数のやり取り・タスクにまたがるもの」に絞る。
  一度きりの依頼は案件化せず通常対応する。
- 期限や担当が不明なまま放置せず、確認が必要な項目は「経緯・メモ」に残す。
