# サイトウォッチ（定期チェック）

トリガー: 「サイトチェック」等の明示的な依頼、および毎日の定期実行（Routine）。

## 目的

`config/watch-sites.md` に登録した自社サイト・競合/業界サイトを毎日巡回し、
変化の有無にかかわらず、その日の状況を必ずレポートする。

## 手順

1. `config/watch-sites.md` を読み、登録URLを取得する。
   - 1件も登録がなければ「監視対象サイト未登録です。config/watch-sites.md にURLを
     追加してください」とだけ報告して終了する（チェックは行わない）。
2. 各URLについて現在の内容を取得する。
3. `projects/site-watch/<URLのスラッグ>.md` に前回のスナップショットがあれば読み込み、
   現在の内容と比較する。初回（スナップショットが無い場合）は「初回登録」として扱う。
4. 変化を検出する。対象は構造的・内容的な変化に絞る（表示のたびに変わる広告・日時表示・
   セッションID等のノイズは無視する）。
   - 自社サイト: 更新箇所、新規/削除ページ、目立つ訴求内容の変更
   - 競合・業界サイト: 新着情報、価格・サービス内容の変更、キャンペーン等
5. 現在の内容で `projects/site-watch/<スラッグ>.md` を上書き更新し、次回比較に備える。
6. 変化の有無にかかわらず、毎回必ず以下のフォーマットでレポートする。

## 出力フォーマット

```
## サイトウォッチ（YYYY-MM-DD）

### 自社サイト
- URL
  変化: あり/なし/初回登録
  内容: （変化の要約。無ければ「特筆すべき変化なし」）

### 競合・業界サイト
- URL
  変化: あり/なし/初回登録
  内容: ...

### 総括
- （全体を通じて注目すべき点があれば1〜2文。無ければ「特記事項なし」）
```

## 注意

- 推測で「変化あり」と報告しない。取得できた内容の比較に基づいてのみ判定する。
- サイトが取得できない（アクセス不可・エラー）場合は「取得失敗」と明記し、変化判定は行わない。
- レポートは簡潔にまとめる。差分の全文転記はせず、要点のみ記載する。
