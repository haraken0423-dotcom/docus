# 売上UP案（オンラインサイト）

トリガー: 「売上UP案」等の明示的な依頼、および毎週月曜の定期実行（Routine）。

## 目的

自社のオンラインサイト（EC・モール店舗）の売上を伸ばすための、実行可能な施策を
定期的に提案する。

## 対象

`config/watch-sites.md` の「自社サイト」のうち、販売が発生するサイト
（例: 自社EC、楽天等のモール店舗）。コーポレートサイト等、販売を伴わないものは対象外。

## 手順

1. `config/watch-sites.md` から対象サイトのURLを取得する。
   - 対象サイトが1件もなければ「売上UP案の対象サイトが未登録です」と報告して終了する。
2. 各サイトの現状を確認する（商品構成、価格表示、キャンペーン・バナー、レビュー、UIなど
   取得できる範囲で）。
3. `projects/site-watch/` に直近のスナップショットがあれば、直近1週間の変化点も踏まえる。
4. `config/watch-sites.md` の「競合・業界サイト」と比較し、参考になる施策・差別化できる点を洗い出す。
5. `projects/sales-growth/history.md` を確認し、直近で提案済みの施策と重複しないようにする。
6. 実行可能な施策を3〜5個、優先度順に提案する。
7. 提案内容を `projects/sales-growth/history.md` に追記する（日付・提案内容の記録）。

## 出力フォーマット

```
## 売上UP案（YYYY-MM-DD週）

### 現状の観察
- サイト名: 気づいた点

### 提案（優先度順）
1. 施策名 — 内容 / 想定効果 / 実施難易度（低・中・高）
2. ...

### 競合からのヒント
- ...
```

## 注意

- 実施のためにサイト改修・広告出稿など費用や契約が発生する施策は、実行前に必ずユーザーの承認を得る
  （行動原則の「金銭・契約」に該当するため）。
- 取得できなかった情報（アクセス数・売上データ等、外部サイトからは分からない指標）は
  「取得不可のため未評価」と明記し、憶測で数値を作らない。
- 前回提案と同じ内容を繰り返す場合は「継続提案」と明記し、新規のように見せない。
